# 高校教师画像抓取系统（面向生命科学耗材销售）设计思路 v0.1

> 状态：讨论稿。目标：让销售在联系一位老师之前，3 分钟内拿到一份可信、带出处的"教师画像卡"。

## 0. 先回答几个关键判断

| 问题 | 结论 |
|---|---|
| 要不要去爬论文门户（知网、Google Scholar 等）？ | **不爬 HTML，走 API。** 生命科学领域用 PubMed E-utilities + OpenAlex 即可覆盖绝大多数英文论文，免费、结构化、合法、稳定。知网反爬强且有版权风险，放到最后，按需人工补。 |
| 全国高校怎么做到"都抓"？ | 不是一次写死 3000 个解析器，而是：**CMS 指纹 + 站点模板（LLM 一次生成、人工确认、缓存复用）+ LLM 兜底抽取 + 校验**。国内高校站点集中在少数几家 CMS（博达 WebPlus、苏迪、学校自研教师主页系统等），模板复用率高。 |
| "skill" 是什么形态？ | 两层：**批量流水线**（本仓库代码，定时跑全国）+ **Claude Skill**（销售/运营按需调用：`给我 XX 大学 XX 学院的老师`、`给我 XXX 老师的画像卡`、`接入一个新学院的师资页`），Skill 内部调用流水线 CLI。 |
| 最有销售价值的信号是什么？ | 1) 老师是否独立 PI、有没有实验室；2) 近 3 年基金（预算）；3) 论文方法学（用什么耗材：细胞培养→培养瓶/板，qPCR→八连管，分子克隆→吸头/离心管）；4) 在招人（扩张）；5) 学校近期耗材招标（竞品与采购节奏）。 |

## 1. 目标与范围

- 公司：元赞智造（yuanzan.com），生命科学核心耗材。
- 目标客户：高校中做湿实验的教师/PI。覆盖学科：生命科学、药学、基础医学/临床医学、生物工程、化学/化工、农学/园艺/植保、食品、环境、材料（生物材料）。
- 覆盖面：全国本科高校（教育部名单约 1300 所本科，优先 "双一流" 147 所 + 医药类/农林类院校）。预估相关学院 1500–2000 个，教师 8–12 万人。
- 不做：登录后数据、学生信息、私人手机号/身份证等敏感信息。

## 2. 数据模型（教师画像卡）

```
Teacher
  ├─ 基本：姓名、拼音/英文名、性别(可选)、学校、学院/系、职称、职务、是否 PI/独立课题组、博导/硕导
  ├─ 联系：邮箱(工作)、办公电话(工作)、办公地址、实验室名称、课题组网站
  ├─ 研究：研究方向(原文)、关键词(归一化)、使用技术(推断：细胞培养/PCR/测序/蛋白纯化/动物实验…)
  ├─ 产出：近 5 年论文（题目、期刊、年份、DOI、第一/通讯标记）、代表作 3 篇
  ├─ 经费：NSFC 等基金（题目、类别、年份、金额）
  ├─ 动态：招聘信息(博后/技术员/研究生)、新闻(获奖、新任职)
  ├─ 销售：产品匹配度打分、推荐产品线、切入话术要点（LLM 生成，附证据）
  └─ 元数据：每个字段的 来源URL + 抓取时间 + 置信度 + 原文片段(evidence)
```

**原则：每个字段可溯源。** 销售看到"邮箱 xxx"时能点开来源页核对。

## 3. 数据源分层

| 层 | 来源 | 价值 | 获取方式 | 难度 |
|---|---|---|---|---|
| L1 | 学院官网师资列表/详情页（如 life.sjtu.edu.cn/T/Index/zc、swywxy.cpu.edu.cn/9902/list.htm） | 姓名、职称、邮箱、方向，**权威** | httpx 抓静态；JS 渲染用 Playwright | 中（异构） |
| L2 | 学校统一教师主页系统（faculty.xxx.edu.cn、life.sjtu.edu.cn/teacher/xxx） | 更全的简历、论文、基金 | 同上，结构更规整 | 低–中 |
| L3 | OpenAlex API（按机构 ROR + 作者名）、PubMed E-utilities | 论文、合作者、消歧 ID | REST API，免费 | 低 |
| L4 | NSFC 基金（LetPub/科学网基金库、国家自然科学基金共享服务网） | 预算信号 | 部分有验证码，优先做可用的镜像库 | 中 |
| L5 | 学校采购/招标公示、中国政府采购网 | 耗材采购节奏、竞品、预算 | 关键词检索 + 解析 | 中 |
| L6 | 招聘信息（学院通知、科学网人才、小木虫） | 扩张信号、联系人 | 关键词检索 | 中 |
| L7 | AMiner、百度学术、X-MOL 课题组页、ResearchGate、ORCID | 补充/交叉验证 | 部分有反爬 | 中–高 |
| L8 | 知网/万方（中文论文） | 中文期刊产出 | 暂不自动抓，按需人工 | 高 |

第一阶段只做 L1–L3，L4 做可行性验证，L5/L6 在试点后再决定。

## 4. 系统架构

```
种子层  →  发现层  →  抓取层  →  解析层  →  增强层  →  实体消歧  →  校验/评分  →  存储  →  输出
高校名单   找学院/    httpx+     模板/      OpenAlex    同名合并      规则+抽样     PG+       画像卡/
学科白名单 师资页URL  Playwright LLM抽取    PubMed/NSFC  ORCID/邮箱    人工复核      对象存储   CRM/飞书
```

### 4.1 种子与发现
- 教育部高校名单 → 学校主页 → "院系设置"页 → LLM 按学科白名单筛出目标学院。
- 学院主页 → 用关键词（师资队伍/教师/专任教师/导师/教授/研究人员/PI）+ sitemap + LLM 导航找到师资列表页。找不到的进入人工待办队列（预计 10–15%）。
- 产出 `college_source` 表：学校、学院、列表 URL、CMS 类型、是否 JS 渲染、状态。

### 4.2 抓取层（稳定性）
- 每域名并发 1、间隔 2–3 秒、随机 UA、遵守 robots、失败指数退避、单页超时 30s。
- 字符集自动检测（大量老站仍是 GBK）。
- **所有原始 HTML 落盘**（对象存储，按 URL 哈希 + 时间），解析规则升级时可离线重跑，不用再打学校服务器。
- 静态优先，检测到内容为空/明显 JS 渲染时才切 Playwright。
- 代理池只在被封时启用，不默认开。

### 4.3 解析层（正确性 + 成本）
三级策略，命中前一级就不走后一级：
1. **站点模板**：对每个列表页/详情页，由 LLM 看一次 HTML 生成 CSS/XPath 规则，自动在 3–5 个样本上验证，通过后入库复用。按 CMS 指纹（如博达 `/xxxx/list.htm` + `/2020/0101/cXXXXaXXXXX/page.htm`）跨校复用。
2. **通用启发式**：姓名（2–4 汉字）、职称枚举、邮箱正则、电话正则、"研究方向/Research"锚点抽段落。
3. **LLM 兜底抽取**：HTML → Markdown → 截断到 6k tokens → 结构化 JSON（Pydantic schema 校验，失败重试一次）。
- 列表页和详情页分别抽取后合并，详情页优先。

### 4.4 增强层
- OpenAlex：`institutions` 用 ROR 查机构 ID，`authors` 按名字（中文拼音 + 英文名多种拼写）+ 机构过滤，取近 5 年 works。
- PubMed：`esearch` 用 `作者[AU] AND 机构[AD]`，`efetch` 取摘要，用摘要/MeSH 推断实验技术 → 映射到产品线。
- NSFC：按姓名 + 单位查近 5 年项目。

### 4.5 实体消歧（最容易出错的地方）
- 主键：学校 + 学院 + 姓名；冲突时用邮箱、ORCID、研究方向相似度、OpenAlex author id 拆分。
- 常见名（王伟、李静…）必须有至少两个佐证（邮箱域名匹配 + 机构一致）才自动合并，否则标记"待人工"。
- 老师调动/退休：定期比对列表页，消失的标 `inactive`，不删除。

### 4.6 校验与质量门禁
- 字段级规则：邮箱域名应属于该校；职称在枚举内；姓名不含"教授/博士"等尾巴；研究方向非空。
- 站点级覆盖率：详情页抽取数 / 列表页人数 ≥ 95%，否则该站点标红。
- 抽样人工复核：每个新接入站点前 20 条 100% 人工看；之后按 3% 抽检。
- 监控：每日成功率、每站点人数环比（跌 >20% 报警）、LLM 成本、被封域名清单。

### 4.7 存储
- PostgreSQL：`school`、`college`、`college_source`、`teacher`、`teacher_field_evidence`、`publication`、`grant`、`crawl_job`、`site_template`。
- 对象存储/本地目录：原始 HTML、PDF 简历。
- 全量字段带 `source_url`、`fetched_at`、`confidence`。

### 4.8 输出（给销售）
- **教师画像卡**（单页 Markdown/HTML，可导出 PDF）：基本信息、研究方向一句话、近 3 篇代表作、基金、推测使用的耗材、推荐产品、建议话术、所有出处链接。
- **学院清单**（Excel/飞书多维表格）：便于区域销售批量筛选。
- 后续可同步 CRM。

## 5. 技术选型（建议）
- Python 3.12，httpx、Playwright、selectolax/lxml、Pydantic、SQLAlchemy + PostgreSQL（试点阶段 SQLite 即可），任务队列用 RQ/Celery 或 Prefect。
- LLM：抽取用小模型（成本），画像卡/话术用大模型。全量约 10 万详情页 × 约 3k tokens，一次性成本可控，模板命中后 LLM 调用量会降到 20% 以下。
- 单机即可跑全国：以每域名 2.5s 间隔计，一个 60 人学院约 3 分钟，跨域名并发 20，全国首轮约 1–2 周，增量更新每季度一轮，论文/基金每月经 API 刷新。

## 6. 合规与风控
- 只采集公开发布的工作联系方式与学术信息，用途限于 B2B 商务沟通，符合《个人信息保护法》对公开信息"合理范围内处理"的要求；不采集私人手机、身份证、家庭信息。
- 不绕过登录、验证码；遵守 robots 与限速；不对学校服务器造成压力。
- 提供"按请求删除"机制；画像卡上注明数据来源与日期。
- 销售使用规范：不群发垃圾邮件，画像用于了解客户而非自动化营销。

## 7. 试点方案（建议 5 所，覆盖不同 CMS 与渲染方式）

| 学校/学院 | 代表的类型 | 目的 |
|---|---|---|
| 上海交通大学 生命科学技术学院（life.sjtu.edu.cn/T/Index/zc + /teacher/ 主页系统） | 自研系统，疑似 JS 渲染，有统一教师主页 | 验证 Playwright 路径与 L2 深度信息 |
| 中国药科大学 生命科学与技术学院（swywxy.cpu.edu.cn/9902/list.htm） | 博达 WebPlus 静态模板 | 验证模板复用（博达覆盖大量高校） |
| 浙江大学 或 复旦大学 生命科学学院 | 另一类 985 自研站 | 验证模板泛化 |
| 一所医学院（如 南京医科大学 基础医学院） | 医学类院校、英文论文多 | 验证 PubMed 增强与消歧 |
| 一所普通一本（如 南京师范大学 生命科学学院） | 典型"长尾"站 | 验证通用启发式 + LLM 兜底 |

**试点验收指标**：列表覆盖率 ≥95%；姓名/职称/邮箱准确率 ≥95%（人工核对 50 条）；论文匹配精确率 ≥90%；单教师平均成本（LLM + 时间）有明确数字；每所学校从"给 URL"到"出画像卡"不超过 1 小时人工介入。

## 8. 分阶段计划
1. 第 1–2 周：数据模型、抓取/解析/校验骨架、SJTU + CPU 两站跑通，产出首批画像卡给销售试用并收集反馈。
2. 第 3–4 周：接 OpenAlex/PubMed/NSFC 增强；产品匹配规则；Claude Skill 封装（三个命令：接入学院、抓学院、出画像卡）；其余 3 所试点。
3. 第 5 周起：发现层自动化（学校 → 学院 → 师资页），监控面板，开始按"双一流 + 医药农林"顺序滚动全国。
